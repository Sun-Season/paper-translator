# 论文翻译工具

## 在另一台 Mac 上使用

1. 安装 Python 3.12，解压整个工具包到自己的文件夹。
2. 双击 **翻译论文.command**。首次运行会自动安装依赖和下载排版资源，需要联网。选择一篇 PDF，再输入自己的 DeepSeek API 密钥。
3. 等待结果目录自动打开，阅读其中的 `paper.pdf`。跨页重排成功时，结果目录里还会有一份“原分页译文.pdf”，便于对照公式和复杂图表。如果已在环境变量或工具目录的 `.env.deepseek.local` 中配置密钥，就只需要选文件。

要导出 Markdown 或更换 PDF 版式，可双击 **其他导出选项.command**。

## 实现与来源

PDF 模式直接调用通过 PyPI 安装的 `pdf2zh_next` 命令。本机使用 PDFMathTranslate-next 2.9.0，底层 BabelDOC 0.6.2 负责版面分析、公式处理和 PDF 重排，最初的单页样例由 Bing 翻译。两个上游包均标注 AGPL-3.0。[PDFMathTranslate-next 仓库](https://github.com/PDFMathTranslate-next/PDFMathTranslate-next) · [BabelDOC 仓库](https://github.com/funstory-ai/BabelDOC)

本项目新增了 macOS 启动器、命令行封装、连续排版、图、公式与文献引用跳转和 Markdown 导出。译文完成后，默认由 LaTeX 重排段落，并按新页码重建导航。Markdown 模式由用户选择的视觉模型识别并翻译文字、转写 LaTeX 和定位插图，本地代码用 pypdfium2 裁图并组装文件。示例目录中的 PDF 是实际翻译结果，Markdown 使用模拟模型回复测试导出。

## 使用方法

在 macOS 上双击 **翻译论文.command**，选择论文。默认把英文译为中文，并将结果保存在原稿旁边的 `论文名-translated` 目录。再次运行会新建带时间戳的目录。

在“其他导出选项”中，PDF 默认选中 **千问视觉翻译 + LaTeX 跟随原稿**：可识别的独立题头直接从原 PDF 保留，包括原文题名、机构、作者排版及题头网页链接。中文版摘要在首页通栏排放。正文沿用识别出的原稿单栏或双栏，原稿中跨栏的大图及其图注占两栏，普通图和公式按栏宽排放。选 **跨页重排（单栏阅读）**，工具会按阅读顺序提取译文段落、重新断行和分页，并把识别出的原图、独立公式嵌回新位置。新页码可能与原稿不同。图或公式放不下时会整体移到下一页。选 **保留原分页（对照阅读）**，则继续使用原稿页码和栏位。扫描页、复杂多栏和未标号图表的识别效果取决于输入 PDF；重排模式会重建图和公式的导航，其他原始 PDF 注释与链接不保证保留。

启动器和命令行视觉后端默认跟随原稿栏数，缺少正文的页沿用就近正文页的栏式。单栏阅读用 `--layout reflow`，对照原稿用 `--layout original`。这些版式共用同一个 PDF 翻译服务。

| 输出 | 适用场景 | 实现方式 |
| --- | --- | --- |
| PDF | 对照原稿阅读，保留栏、图表和公式的位置关系 | PDFMathTranslate-next 分析版面，替换正文并重新排版，尽量保留原图和公式。译文长度会影响换行和字号。 |
| Markdown | 编辑正文、公式，单独使用图片 | 视觉模型按页识别阅读顺序，将公式转为 LaTeX。程序用模型返回的边界从原 PDF 裁出插图，保存为默认 400 DPI 的 PNG。 |

选择 DeepSeek 文字翻译时，工具将待译文字发给 DeepSeek 官方接口。可在工具目录的 `.env.deepseek.local` 中设置 `DEEPSEEK_API_KEY`，或通过环境变量传入。工具不保存对话框输入的密钥。默认模型为 `deepseek-flash`，可用环境变量 `DEEPSEEK_MODEL` 更换。首次启动排版引擎会下载模型和字体。若显式指定 `--model`，PDF 默认改用该模型的兼容接口。用 `--pdf-service deepseek` 可以在双格式导出时让 PDF 用 DeepSeek、Markdown 用指定的视觉模型。

在重排版中，点击正文里的图号或公式引用可定位到图文区域；点图注或公式旁的“返回正文”可返回相应正文。文末按原编号分条排版。对于识别到的方括号数字引用，例如 `[79, 21]`，两个数字可以分别点击，直接定位到对应条目的开头。当前主要支持从 1 开始连续编号的书目。识别出原稿书目时，重排版沿用原始条目。若图注边界等版式检查未通过，工具自动交付原分页译文，同时生成“版式说明.txt”指出原因。

Markdown 模式会把每页预览图发送给所选视觉模型，需要支持图片输入的 Chat Completions 接口。使用付费接口时，费用按服务商规则计算。

Markdown 输出包含 `paper.md` 和有插图时生成的 `figures/`。移动或分享时请保留两者的相对位置。显示公式需要支持 LaTeX 的编辑器。复杂矩阵、细小上下标、双栏跨页段落和插图裁剪边缘值得对照原稿检查。扫描稿优先选择 Markdown。提高导出 DPI 可改善矢量图的栅格化效果，清晰度仍受原图限制。

## 命令行

在工具目录中运行。以下示例假定已安装依赖。

```sh
.venv/bin/python translate.py "/路径/论文.pdf"
```

Markdown 和两种格式同时导出都需要视觉模型。把下面的模型名替换为服务商提供的实际名称。可在终端中安全读取密钥，例如在 zsh 下执行 `read -rs 'OPENAI_API_KEY?API Key: '; export OPENAI_API_KEY`。

```sh
export OPENAI_BASE_URL="https://api.openai.com/v1"
export PAPER_MODEL="你的视觉模型名称"
.venv/bin/python translate.py "/路径/论文.pdf" --format md --dpi 400
.venv/bin/python translate.py "/路径/论文.pdf" --format both --out "/路径/两种译文"
```

用 `--source-lang en --target zh` 设置语言。命令行的 `--out` 必须指向尚未创建的目录。只有整次转换成功后才会发布结果。长论文会逐页调用视觉模型，中断后重跑会从第一页重新开始。

## 在新环境安装

使用 Python 3.12，如需从命令行手动安装，在本目录执行以下命令。PDF 引擎及其依赖需要较多磁盘空间。

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

## PDF 任务执行与恢复

执行器按论文内容、语言、模型配置和翻译引擎版本区分任务。DeepSeek 完成翻译后，先把原分页译稿原子写入本地任务目录，再开始重排。同一任务再次运行时会复用该译稿。默认缓存位置为 `~/Library/Caches/paper-translator/jobs/`，可用 `PAPER_JOB_DIR` 更换。删除对应目录会清除该任务的缓存。

重排时，工具用原稿段落的位置、栏界和行距重组译文碎片，并在最终 PDF 中检查记录的文本衔接。结果目录中的 `任务报告.json` 记录重排的验收结果。若无法确认衔接或图注边界，工具交付原分页译稿并说明原因。检查不评价翻译是否忠实，也不能发现所有语义缺失。

已有原分页译稿时可用 `--translated-pdf "/路径/原分页译文.pdf"` 从排版阶段运行。请提供同一篇论文的原稿和译稿，工具会检查页数，但不能仅凭页数证明两份文件匹配。

执行器参考了 DeepSeek 官方组织发布的 Super-agent 研究原型的任务隔离与交付恢复设计。论文执行器使用本项目的 Python 实现。[原型与设计范围](https://github.com/deepseek-ai/dsh-superagent-prototype) · [执行与恢复](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/HEAD/docs/003-execution.md)

双栏或单栏重排时，工具从原稿提取能识别的编号陈列公式，以等比例 PDF 矢量裁片嵌回正文。交付前用相同分辨率对照原稿和成品中的公式墨迹，任务报告列出通过检查的编号。该检查覆盖已识别的独立公式；行内数学和未编号公式不在此清单中。

DeepSeek 的正常 PDF 重排流程还会检查含大型数学运算符的行内段落。对支持的字体，工具从源 PDF 获取字形轮廓与位置，单独保留求和、连乘及上下限，再由 DeepSeek 翻译公式间的文字。模型不能改写或调换公式；新翻译的文字段落会缓存。任务报告分别列出已验收的编号公式和行内裁片数。对于已有原分页译稿，加上 `--repair-inline` 可执行此步骤，未命中的段落会调用 DeepSeek 并按用量计费。图片扫描稿、未知数学字体及未识别段落不在这项保真检查范围内。

## LaTeX 双栏排版

双击 **翻译论文.command** 即可使用跟随原稿栏式的 LaTeX 排版。命令行可用 `--layout reflow-two --backend latex`。本机需要 Tectonic（macOS 可用 `brew install tectonic`）或带 xeCJK 宏包的 XeLaTeX，以及宋体 Songti SC 和 Times New Roman。Tectonic 首次运行会联网下载标准 TeX 宏包。

这个后端共用既有的段落提取、DeepSeek 译文和受保护的公式裁片，改由 LaTeX 执行中文断行、双栏分页及图文放置。它不会从原 PDF 自动还原作者的 LaTeX 源码，也不能补全输入阶段遗漏的字符。如需 MuPDF 双栏版，可指定 `--backend mupdf`。

LaTeX 版使用宋体（Songti SC）排中文、Times New Roman 排英文与数字，集合运算符等数学字符由数学字体输出。较长的受保护公式独立排放，图注用细线、较小字号和加粗图号区别于正文。对于有明确横线边界且步骤编号连续的伪代码，工具保留原稿矢量块与原文语言，避免翻译或换行打乱步骤。

双击启动器默认使用千问视觉翻译和 LaTeX 排版。模型名为 `qwen3-vl-plus`，接口为 `https://maas.qianwenaiapi.com/compatible-mode/v1`。可设置 `QWEN_API_KEY` 或在启动时输入密钥。Pandoc 读取视觉模型生成的 Markdown，Tectonic 或 XeLaTeX 编译中文 PDF。图表按宽度排放，跨页译段先与原稿的标题和图表位置核对。首次编译可能需要下载 TeX 宏包。

复用已经生成的视觉译稿时，将 `paper.md` 和 `figures/` 放在同一目录，然后运行 `python translate.py 原稿.pdf --vision-draft 译稿目录/paper.md --out 新结果目录`。不指定模型时，本命令复用同目录的 `table-translations.json`，不调用翻译接口。需要补译表内说明时，传入 `--model` 和 `--base-url`，并设置对应密钥。

视觉译稿导出 PDF 时，工具按原页表题和横线定位表格，利用文字坐标恢复行列，在 LaTeX 中重建表头、分组及数据行。数值表按原稿坐标排印，保留指标、上下箭头、表线及行底色。工具将文字表中的长说明译成中文，数值通过核对后才写入。未配置模型且无译文缓存时，工具保留原文，并生成待译说明清单。每张重建表的源代码保存在结果目录的 `tables/` 中。正文表号跳到对应表题；点击表题中的表号可定位表体。没有可靠边界的表格继续使用视觉译稿的表示。

双栏 PDF 会查找正文首次提到图号的段落，据此调整图片的提交顺序。图注和图片一起排版；跨栏图片与表格分别进入浮动队列。实际距离取决于图高和当前页可用空间。

默认的视觉 PDF 导出在整本 LaTeX 文件编译后运行对象验收。工具从原 PDF 建立编号图表清单，将译稿裁片配准到原页，再检查成品中的图像摘要、目标页、表体、子表及内部链接。图与首次引用的页距属于排版偏好，不触发重试。

可定位的正文错裁、缺失图块或重复子表最多进行两轮局部修复，每轮都重新编译并验收整本 PDF。问题集合没有缩小、缺少可靠修复依据或达到次数上限时，保留此前验收结果较好的可读版本。结果目录的 `质量验收.json` 记录原稿对象、每轮问题与修复动作；仍有未解决的硬错误时另附 `待复核.txt`。这项验收覆盖已识别的版面对象，不代表逐句翻译质量或所有公式均已校对。LaTeX 的缺字和越栏提示仍记录在 `LaTeX版式检查.txt`。

中文译稿的页面缓存带有正文语言检查。工具会对新返回的页面和旧缓存重新检查英文叙述，再写入已核验页面。引用、代码、公式、命令示例、工具名、作者和文献条目按内容判别；半页英文不会因段首出现中文图号而跳过。可靠匹配邻页的段落只有在相应译页中找到中文证据后才去重。本页漏译则局部补译，保留受保护片段并核对原有数字。原页归属或去重证据无法核实时，工具不会缓存该判别为成功。

复用旧 Markdown 时，若仍有待判别的英文，请用 `--vision-draft` 配合 `--model` 和 `--base-url`。工具读取同一份原 PDF，按原页标记核对，不必重译整篇。结果目录的 `正文语言检查.json` 记录段落归属、处理方式和去重依据。

视觉 PDF 导出会单独识别原稿中有三条横线和连续步骤号的算法框。译文按原稿的步骤、缩进和线宽重排，公式引用靠右。验收器检查整个算法框是否在同页、三条横线是否实际绘制、步骤号是否完整，以及可解析的公式引用是否有链接。无法还原已识别算法时，结果列入待复核清单。

### Markdown 和 LaTeX 在视觉 PDF 验收循环中的作用

1. **Markdown 保存译文，也是每轮修改的起点。** `paper.md` 用原稿页标记保留译段归属，用公式标记和图片路径标出数学内容和插图。导出前，工具结合原页检查可疑英文和断裂的公式。视觉复核提出的文字替换和补译写回候选译稿。需要重裁插图时，工具从原 PDF 生成新裁片，并更新候选译稿中的图片路径。
2. **LaTeX 把候选译稿排成整篇 PDF。** Pandoc 解析 Markdown，工具结合原稿的栏式和图表位置生成 LaTeX，处理段落、公式、图表、算法框和交叉引用，再调用 Tectonic 或 XeLaTeX 编译。每次接受修改进入下一轮，都会重新生成并编译整篇。文档级格式由统一排版参数控制。视觉模型可修改译文、插图裁框，以及对象的单栏／跨栏和表格列宽比例。
3. **成品决定这一轮是否采用。** 程序在实际 PDF 上检查题头、图表、算法和链接。启用视觉复核时，千问再对照原页和成品页检查修改效果。工具根据复查结果选择版本，使最终交付的 Markdown、插图和 PDF 对应同一轮。

### 千问成品视觉复核

视觉 PDF 导出配置模型时，默认在原有确定性验收之后运行视觉审阅。工具渲染每一张原页和成品页，按译稿与 PDF 的文字重合程度建立跨页对应关系，再把两侧的图像和文字交给同一视觉模型。模型可指出原文与译文的具体差异，提出局部文字修改、补充遗漏内容或调整插图裁框，并说明下一轮该看什么。无法定位、缺少原文依据或超出执行器能力的意见会留在报告中，模型回复不能执行命令或改写程序。

默认最多审阅五轮，可用 --max-review-rounds 设置 1 到 10 轮，每轮重新编译整篇，重新运行确定性验收和视觉审阅。没有可执行动作、审阅不完整、达到上限或新候选没有改善时停止。报告中的模型判断仍可能有误。最终 PDF 对应的轮次可在 `每轮修改记录.md` 中查看；`视觉审阅记录.json` 另含逐页意见、原文引文、实际补丁、复查结论和 PDF 的 SHA-256。复用译稿并指定模型将联网审阅；使用 `--no-visual-review` 可跳过视觉审阅。复用译稿而未指定模型时仅进行确定性验收。

## 第二版任务恢复

默认入口在输出目录旁创建同名的 `.job` 目录。该目录保存任务状态、原始逐页回复、已完成阶段的检查点、视觉审阅回复和每轮候选。接口错误会将任务记为 interrupted。用相同命令和输出目录重启时，工具恢复已完成阶段，从最近检查点重跑未完成阶段。参数、源文件或工具代码改变时，必须使用新的输出目录。成功后才能出现正式交付目录，仍有质量问题时任务状态为 needs_review。

`task.json` 记录当前阶段和异常；`requests/` 仅记录请求摘要、阶段、模型和 HTTP 状态，避免保存密钥和图像请求正文。403 会保留并中断任务，不自动认定为限流。视觉复核请求失败也会中断，已成功的审阅回复按请求内容复用。`rounds/` 保存每轮候选与审阅结果。所有工作产物默认留在本机，可能占用较多磁盘空间。

`object_policy.py` 是翻译和视觉审阅共用的自然语言要求，包括题头、字体、栏式、缩进、表格和算法保真。排版代码仍负责执行样式，确定性验收只覆盖已经实现的检查。实际参数由 layout_policy.py 提供，写入每轮 layout.json。字体、正文缩进和栏间距直接生成 LaTeX 参数。对象级 span 和 column_widths 分别控制浮动环境及表格列宽。视觉执行器支持改文、补文、重裁图片和 layout 修改；其他建议记录为待复核。

验证覆盖阶段中断后恢复、拒绝不同参数复用任务、候选复核后选择等路径。自动测试使用模拟服务响应，实际模型与最终页面质量仍需真实论文验证。

### 视觉循环调整版式

每轮导出生成 layout-objects.json，包含可调整对象的编号和原页。模型的 layout 动作必须引用其中的对象，提供原文依据和复查条件。span 可以为 source、single 或 wide；column_widths 是总和为 1 的列宽比例。只有表格可修改列宽，列数必须与识别结果一致。对象级调整保存在 layout.json，确定性修复的每次重编译都会传递该文件。

原生说明性表格按比例设置可换行单元格；数值表保留内容、表线和装饰，按列映射横向坐标。Markdown 表格也支持比例列宽，双栏中的单栏表使用 tabular，跨栏长表使用 longtable。图、表和已识别算法可以调整单栏／跨栏。无效参数会被拒绝，编译失败或复查未改善的候选不会替换已复核版本。

本次验证包含 40 项自动测试以及单栏、跨栏表格的实际 LaTeX 编译。π₀.₅ 已实际完成整篇导出和两轮视觉审阅，生成 22 页 PDF。第二轮未改善，选择第一轮。结果为 needs_review，题头原样保留仍未通过确定性验收。

### 图组、引用与跨页列表

导出器将纯数字的 LaTeX cite/citep/citet 引用转为可链接的编号引用，并保留有序列表的起始编号。同一图注前出现多个裁片时，工具依据原页图注、图像位置和前一图注边界恢复完整图组。首页摘要前存在插图时，题头识别会结合图像位置和文字间距确定头部边界。图内连续标签混入正文时，视觉译稿复核会重新读取相关原页，生成新的正文和完整图块。复用译稿且指定模型时也运行这项复核。

π₀.₅ 的五处问题修订稿已完成两轮视觉审阅，程序对象检查通过，引用原始命令未残留，列表续号及原稿题头已核验。视觉结果仍为 needs_review，选用第一轮候选，不能据此声称整篇翻译质量全部通过。

### 首页和摘要栏式

摘要按原稿摘要叙述行的宽度单独识别栏式，原稿单栏就单栏，原稿双栏就双栏。首页题头、首图、图注、摘要与引言的原有顺序优先保留，首页首图不参与向后移动的引用距离优化。Introduction 前增加 10 bp 间距。中文长度变化仍会影响断行和分页。π₀.₅ 已完成这项修改后的整篇导出并通过程序对象检查，本轮没有重新调用模型做全文视觉审阅。

摘要标签统一使用英文 Abstract，采用 Times New Roman 加粗斜体；摘要正文加粗，栏式继续跟随原稿。π₀.₅ 的实际 PDF 已核对标签和中文正文所用字体。
